# Review records

Store durable implementation and architecture reviews here when they contain
findings that affect later work. Use one file per review:

```text
YYYY-MM-DD-<scope>-<reviewer>.md
```

Keep records bounded and link them from the relevant implementation plan or
ADR when they change a decision. Do not store secrets, raw service responses,
or full test logs. Historical reviews remain useful; mark their status rather
than deleting them.

Use [`TEMPLATE.md`](TEMPLATE.md) for new records.
